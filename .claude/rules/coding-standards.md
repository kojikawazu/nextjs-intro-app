# コーディング規約

- **言語**: TypeScript strict モード（strict: true）
- **パッケージマネージャ**: pnpm を使用（npm, yarn は使用しない）
- **Linter / Formatter**: ESLint + Prettier でコード品質を担保
- **環境変数**: 設定値は環境変数で管理（.env）
- **シークレット禁止**: シークレット・認証情報をハードコードしない

## 型・定数・スキーマの配置

型・定数・スキーマは **参照範囲** で置き場所を決める。判断軸は「**そのシンボルを参照するファイルが 1 つに閉じるか**」。

| 参照範囲 | 置き場所 |
|---|---|
| **1 ファイルに閉じる** | その定義ファイル内に置く（`export` しない） |
| **2 ファイル以上** / レイヤ・機能をまたぐ | ソースルート直下の専用ディレクトリへ集約して `export` |

### ディレクトリを切る（単一ファイルにまとめない）

- 集約先は **`src/types/` / `src/constants/` / `src/schemas/`**。**ディレクトリ名は複数形**で統一する。
- `src/lib/type.ts` / `src/lib/constants.ts` / `src/lib/validation.ts` のように **1 ファイルへ全部を詰め込む形は禁止**。必ずドメイン単位でファイルを分ける（`types/task.ts` / `constants/task.ts` / `schemas/task.ts`）。
- **`lib/` `utils/` の下に型・定数・スキーマを置かない。** `lib/` は「関数の置き場」であり、値・型・検証と分離する。

### 運用ルール

- **最初から集約しない。** まず定義ファイル内に書き、**2 箇所目の参照が発生した時点で昇格**させる。先回りの共通化は、使われない共通型と不要な依存を増やす。
- **昇格時は元ファイルに残さない**（re-export も含む）。定義は常に 1 箇所。
- **barrel（`types/index.ts` 等の一括 re-export）は作らない。** 循環参照・バンドル肥大・tree-shaking 阻害の原因になる。`import type { Task } from '@/types/task'` と実ファイルを直接 import する。

### 定数

- **マジックナンバー・マジック文字列を直接書かない。** 分岐条件・API パス・上限値・リトライ回数などのリテラルは名前付き定数にする。
- **`as const` を付ける。** 付けないとリテラル型が `string` / `number` に広がり、union の導出や補完が効かなくなる。命名は `UPPER_SNAKE_CASE`。
- **union リテラルの元になる定数は、導出される型と同じファイル（`types/`）に同居させる。** `constants/` と `types/` に分けると値と型が往復参照になり、片方だけ更新される事故が起きる。
- **環境変数は定数ではない。** 環境ごとに値が変わるもの（ベース URL・キー・フラグ）を `constants/` に置かない（ビルド時に特定環境の値が埋め込まれる）。`constants/` に置くのは**全環境で不変な値**だけ。

### スキーマ（Zod）

- バリデーションは **Zod に統一**する（`yup` / `joi` / 自前検証関数と混在させない）。
- **スキーマを単一の真実とし、型は `z.infer<typeof schema>` で導出する。** 同じ形を手書きで二重定義しない。導出した型を `types/` に再定義しない。
- 外部入力（API レスポンス・`JSON.parse`・フォーム入力）は `unknown` で受け、**Zod で `parse` してから**内部で使う。
- **検証を伴わない純粋な型は `schemas/` に置かない**（`types/` へ）。`schemas/` に置くのは「実行時に `parse` するもの」だけ。

```
src/
├── repositories/   # 外部 I/O（通信・ストレージアクセスはここだけ）
├── schemas/        # Zod スキーマ
├── lib/            # 純粋ユーティリティ（通信しない）
├── constants/      # 値
└── types/          # 型
```
