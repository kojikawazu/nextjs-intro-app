## 1. プロジェクト背景

### 1.1 背景

フリーランスエンジニアとしての案件獲得および技術的ブランディングの強化を目的に、自身のスキル・経歴・実績を一元的に発信するポートフォリオサイトを構築する。従来のSNSプロフィールや職務経歴書だけではカバーできない、技術スタック・プロジェクト経験・問い合わせ導線を統合したワンストップのプロフェッショナルサイトが求められている。

### 1.2 目的

- フリーランスエンジニアとしての認知度向上と案件獲得チャネルの確立
- 採用担当者・発注企業への技術力の効果的な訴求
- SNS（X、GitHub、Zenn、Qiita）を含む複数チャネルへの流入ハブとしての機能
- サイト経由での問い合わせ・商談機会の創出

### 1.3 プロジェクト概要

Next.js 14（App Router）を基盤としたシングルページアプリケーション（SPA）形式のポートフォリオサイト。Google Cloud Run 上に Docker コンテナとしてデプロイし（GitHub Actions による CI/CD）、ポートフォリオデータは Google Cloud Storage（プライベートバケット）から動的に取得する。お問い合わせフォームは Resend API を利用してメール送信を行う。

## 2. ステークホルダー

### 2.1 主要ステークホルダー

| ステークホルダー | 役割 | 関心事項 |
|------------------|------|----------|
| サイトオーナー（フリーランスエンジニア） | プロジェクトオーナー・開発者 | 案件獲得、ブランディング、技術訴求 |
| 採用担当者 | 主要ターゲットユーザー | エンジニアのスキル・経歴の確認、連絡手段 |
| 開発外注検討企業 | 主要ターゲットユーザー | 技術力の評価、プロジェクト実績の確認、見積もり依頼 |
| 技術パートナー候補 | ターゲットユーザー | 技術スタックの確認、協業可能性の検討 |
| 技術コミュニティのエンジニア | ターゲットユーザー | 技術情報の参照、SNSプロフィールへのアクセス |

### 2.2 ユーザーペルソナ

**ペルソナ1: 採用担当者（田中さん）**
- IT企業の採用マネージャー
- エンジニア候補者のスキルセットと実務経験を効率的に確認したい
- 職務経歴書だけでは判断しにくい技術力を可視化した情報を求めている

**ペルソナ2: 開発外注検討企業（鈴木さん）**
- 中小企業の事業責任者
- 自社サービスの開発パートナーを探している
- 実績・技術スタック・対応可能フェーズを一目で把握したい

**ペルソナ3: 技術コミュニティのエンジニア（佐藤さん）**
- 同業のソフトウェアエンジニア
- 技術ブログやGitHubリポジトリへのリンクからスキル情報を辿りたい

| Footerセクション | コピーライト表示 |
| ナビゲーション | 固定ヘッダー、デスクトップ/モバイル対応、スムーズスクロール |
| データ管理 | Google Cloud Storageからのポートフォリオデータ取得 |
| メール送信 | Resend APIによるお問い合わせメール送信 |
| SEO対策 | メタデータ、OGP、Twitterカード、robots設定 |
| レスポンシブデザイン | モバイル・タブレット・デスクトップ対応 |
| デプロイ | GitHub Actions 経由で Cloud Run への自動デプロイ |

### 3.2 スコープ外（Out-of-Scope）

| カテゴリ | 内容 | 備考 |
|----------|------|------|
| ユーザー認証 | ログイン機能、管理画面 | データはGCS上で直接管理 |
| CMS | コンテンツ管理システム | JSONファイルベースの運用 |
| ブログ機能 | 記事の投稿・管理 | Zenn/Qiitaへの外部リンクで代替 |

| EC機能 | 商品販売、決済処理 | 対象外 |
| アクセス解析 | Google Analytics等の埋め込み | 将来対応を検討 |
| ダークモード切替 | テーマの動的切替 | ダーク系テーマで固定 |

## 4. 制約事項・前提条件

### 4.1 制約事項

| 分類 | 制約内容 |
|------|----------|
| 技術制約 | Next.js 14（App Router）、TypeScript、Tailwind CSSを使用すること |
| インフラ制約 | Cloud Run のコンテナ環境で動作すること |
| データストレージ | Google Cloud Storageのプライベートバケットを使用すること |
| メール送信 | Resend APIを経由すること（RESEND_API_KEY、MY_MAIL_ADDRESS、RESEND_FROM_EMAILの環境変数が必要） |
| 言語 | サイトの表示言語は日本語のみ |
| SPA構成 | シングルページアプリケーション（ページ遷移なし） |
| 予算 | Cloud Run 無料枠 + GCS 無料枠 + Resend 無料枠の範囲で運用可能であること |

### 4.2 前提条件

| 分類 | 前提内容 |
|------|----------|
| 環境 | Google Cloud（Cloud Run + GCS）、Resend の各アカウントが利用可能であること |
| データ | ポートフォリオデータはJSON形式でGCSバケットに格納されていること |
| 開発 | 開発環境ではsample.jsonによるローカルフォールバックのロジックが存在する（ただし `sample.json` はリポジトリに未同梱のため、手動配置が必要） |
| ブラウザ | モダンブラウザ（Chrome、Firefox、Safari、Edge）の最新版をサポート対象とする |
| ネットワーク | ユーザーがインターネットに接続していること |
| 運用 | サイトオーナー自身が開発・運用を行う（専任の運用チームはない） |

| KPI | 目標値 | 測定方法 | 期間 |

### 5.2 技術KPI

| KPI | 目標値 | 測定方法 | 備考 |
|-----|--------|----------|------|
| PageSpeed Insightsスコア（Performance） | 90点以上 | Google PageSpeed Insights | モバイル・デスクトップ両方 |
| SEOスコア | 90点以上 | Lighthouse SEO audit | メタデータ・構造化データの最適化 |
| アクセシビリティスコア | 90点以上 | Lighthouse Accessibility audit | ARIA属性・セマンティックHTML |

| ビルドエラー率 | 0% | GitHub Actions ビルドログ | CI/CD の安定性 |

### 5.3 ユーザー体験KPI

## 6. リスクと対策

| リスク | 影響度 | 発生確率 | 対策 |
|--------|--------|----------|------|
| GCSからのデータ取得失敗 | 高 | 低 | 開発環境でのローカルフォールバック、APIレスポンスキャッシュ（s-maxage=300, stale-while-revalidate=86400） |
| Resend APIの障害 | 中 | 低 | エラーメッセージの表示、再送信の案内 |
| Cloud Run の無料枠超過 | 中 | 低 | 静的キャッシュの活用、APIコール数の監視 |
| お問い合わせスパム | 中 | 中 | バリデーションによる最低限の防御（将来的にreCAPTCHA導入を検討） |
| 個人情報の漏洩 | 高 | 低 | サーバーサイドでの環境変数管理、開発環境でのみエラーログ出力 |

## 7. 用語定義

| 用語 | 定義 |
|------|------|
| SPA | Single Page Application。ページ遷移なしで全コンテンツを単一ページ内に表示するWebアプリケーション形式 |
| GCS | Google Cloud Storage。Google Cloudが提供するオブジェクトストレージサービス |
| Resend | メール送信APIサービス。トランザクションメールの送信に使用 |
| App Router | Next.js 13以降で導入されたファイルシステムベースのルーティング機構 |
| OGP | Open Graph Protocol。SNSでリンクを共有した際のプレビュー情報を定義するプロトコル |
| Atomic Design | UI設計手法。Atoms、Molecules、Organismsの階層でコンポーネントを構築する |
| FCP | First Contentful Paint。ブラウザが最初のDOM要素をレンダリングするまでの時間 |
