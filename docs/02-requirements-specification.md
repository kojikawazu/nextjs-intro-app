## 3. 非機能要件サマリー

非機能要件の詳細は `04-non-functional-requirements.md` を参照のこと。以下に概要を記載する。

### 3.1 パフォーマンス

| 項目 | 要件 |
|------|------|
| ページ読み込み速度 | PageSpeed Insights Performance スコア 90点以上 |
| API応答時間 | ポートフォリオデータ取得API 500ms以内（キャッシュ利用時） |
| キャッシュ戦略 | s-maxage=300秒、stale-while-revalidate=86400秒 |
| 画像最適化 | Next.js Imageコンポーネントによる自動最適化、priority属性の適切な設定 |

### 3.2 セキュリティ

| 項目 | 要件 |
|------|------|
| 入力バリデーション | クライアントサイド（Zod）+ サーバーサイド（正規表現+長さチェック）の二重バリデーション |
| 環境変数管理 | APIキー、メールアドレス等の機密情報は環境変数で管理し、クライアントに露出しない |
| 外部リンク | SNSリンクにrel="noopener noreferrer"を付与 |
| エラーログ | 本番環境では詳細なエラー情報をクライアントに返さない（開発環境のみconsole出力） |
| GCSバケット | プライベートバケットを使用、サービスアカウント認証による安全なアクセス |

### 3.3 可用性・信頼性

| 項目 | 要件 |
|------|------|
| 稼働率 | 99.9%以上（Cloud Run プラットフォームに依存） |
| エラーハンドリング | データ取得失敗時のフォールバック、ユーザー向けエラーメッセージ、リロード導線 |
| グレースフルデグラデーション | GCS障害時でも開発環境ではローカルデータで動作継続 |

### 3.4 保守性

| 項目 | 要件 |
|------|------|
| コンポーネント設計 | Atomic Design（Atoms/Molecules/Organisms）による階層的コンポーネント構造 |
| 型安全性 | TypeScriptによる完全な型定義（PortfolioData型を起点とした型階層） |
| コード品質 | ESLint + Prettier + TypeScript strict mode による静的解析 |
| データとUIの分離 | ポートフォリオデータはJSON外部化し、UIコードとコンテンツを分離 |

### 3.5 レスポンシブデザイン

| 項目 | 要件 |
|------|------|
| ブレークポイント | Tailwind CSS標準（sm:640px, md:768px, lg:1024px, xl:1280px） |
| モバイル対応 | 全セクションがモバイル画面で正常に表示・操作可能であること |
| タッチ操作 | モバイルメニュー、ボタン、リンクがタッチ操作に対応していること |

### 4.3 API仕様

#### GET /api/portfolio

ポートフォリオデータを取得する。

| 項目 | 内容 |
|------|------|
| メソッド | GET |
| レスポンス（成功） | 200 OK, PortfolioData JSON |
| レスポンス（失敗） | 500 Internal Server Error, `{ error, details, timestamp }` |
| キャッシュ | `Cache-Control: public, s-maxage=300, stale-while-revalidate=86400` |

#### POST /api/contact

お問い合わせメールを送信する。

| 項目 | 内容 |
|------|------|
| メソッド | POST |
| Content-Type | application/json |
| リクエストボディ | `{ name: string, email: string, message: string }` |
| レスポンス（成功） | 200 OK, `{ success: true, message: string, messageId: string }` |
| レスポンス（バリデーションエラー） | 400 Bad Request, `{ error: string }` |
| レスポンス（送信失敗） | 500 Internal Server Error, `{ error: string }` |

**サーバーサイドバリデーションルール:**

| フィールド | ルール |
|------------|--------|
| name | 必須（空文字不可） |
| email | 必須（空文字不可）、正規表現 `/^[^\s@]+@[^\s@]+\.[^\s@]+$/` に合致 |
| message | 必須（空文字不可）、最大5,000文字 |

## 5. 環境変数一覧

| 変数名 | 必須 | 説明 | 利用箇所 |
|--------|------|------|----------|
| RESEND_API_KEY | 必須（本番） | Resend APIキー（re_で始まる） | メール送信 |
| MY_MAIL_ADDRESS | 必須（本番） | お問い合わせメールの受信先アドレス | メール送信 |
| RESEND_FROM_EMAIL | 必須（本番） | メール送信元アドレス | メール送信 |
| GCS_PRIVATE_BUCKET_NAME | 任意 | GCSバケット名（デフォルト: intro_k_pri_bucket） | データ取得 |
| GCS_JSON_PATH | 任意 | GCS内JSONファイルパス（デフォルト: json/navbar_intro.json） | データ取得 |
| GOOGLE_APPLICATION_CREDENTIALS | 任意 | GCSサービスアカウントキーファイルパス（開発用） | データ取得 |
| GOOGLE_CLOUD_PROJECT_ID | 任意 | Google CloudプロジェクトID | データ取得 |

| GOOGLE_CLOUD_CLIENT_EMAIL | 実質未使用 | GCSサービスアカウントメールアドレス（同上） | データ取得 |
